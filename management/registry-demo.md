# Registry Demo Commands

Copy-paste-ready commands demonstrating the validation registry across the
three main surfaces: the Java CLI (`ae-pattern-validator`), the Python
consistency tooling (`scripts/validate_consistency.py`,
`scripts/generate_status_tables_from_yaml.py`), and direct YAML queries against
`cr-*.yaml` for the `category:` and `lifecycle:` taxonomies.

All commands run from the repository root unless noted. The Java CLI expects
the fat jar built via:

```bash
cd ae-pattern-validator && mvn -q clean package -DskipTests
JAR=ae-pattern-validator/target/ae-pattern-validator-0.1.0-SNAPSHOT-exec.jar
```

(All subsequent `java -jar $JAR ...` examples assume `$JAR` is set.)

---

## 1. Pattern Validation

### 1.1 Instance Mode (concrete algorithm strings)

```bash
java -jar $JAR "AES-256-GCM"
java -jar $JAR "SHA-512"
java -jar $JAR "ML-KEM-768"
java -jar $JAR "ChaCha20-Poly1305"
```

Tabular output: status (OK / WARN / ERROR), pattern, resolved family, OID,
deviations. Exit code 0 if all valid.

### 1.2 Template Mode (wildcards and enumerations allowed)

```bash
java -jar $JAR --template "AES-[128|192|256]-GCM"
java -jar $JAR --template "ECDSA-{ellipticCurve}-{hashAlgorithm}"
java -jar $JAR --template "SLH-DSA-*"
```

Templates carry parameter placeholders (`{name}`) and enumerations
(`[a|b|c]`). Useful for CycloneDX `algorithmProperties.primitiveType` strings.

### 1.3 Authority-Specific Validation

```bash
# Same pattern, different deployment-status lens
java -jar $JAR --authority nist "AES-128-GCM"     # OK — NIST approves AES-128
java -jar $JAR --authority cnsa "AES-128-GCM"     # WARN:DISALLOWED_VALUE — CNSA 2.0 mandates AES-256 only
java -jar $JAR --authority bsi  "AES-128-GCM"     # OK — BSI TR-02102-1 Table 3.1
```

```bash
# Triple-DES across authorities
java -jar $JAR --authority nist "3DES-CBC"        # WARN (deprecated)
java -jar $JAR --authority bsi  "3DES-CBC"        # ERROR (disallowed by TR-02102-1)
```

Authority IDs: `nist | bsi | cnsa | iana | ietf | cabf`. Default is `nist`.

### 1.4 Detecting Broken / Withdrawn Algorithms

```bash
java -jar $JAR "MD5"                              # ERROR — broken (collision attacks)
java -jar $JAR "SHA-1"                            # ERROR — broken (SHAttered)
java -jar $JAR "RC4"                              # ERROR — broken
java -jar $JAR "DES-CBC"                          # ERROR — withdrawn (FIPS 46-3 withdrawn 2005)
```

## 2. OID Lookup

```bash
# Forward: pattern -> OID is shown in the OID column of normal output.
# Reverse: OID -> pattern + family.
java -jar $JAR --oid 2.16.840.1.101.3.4.1.46      # AES-256-GCM
java -jar $JAR --oid 1.2.840.113549.1.1.11        # RSASSA-PKCS1-SHA-256
java -jar $JAR --oid 2.16.840.1.101.3.4.3.17      # ML-DSA-87
java -jar $JAR --oid 1.3.6.1.5.5.7.6.1            # X.509 signature OID example
```

Multiple OIDs in one call:

```bash
java -jar $JAR --oid 2.16.840.1.101.3.4.1.46 1.2.840.113549.1.1.11
```

## 3. Artifact Analysis

Output: subject, issuer, serial, signature algorithm + public key algorithm
(with OID, family resolution, and authority assessment per algorithm).

### 3.2 CMS / PKCS#7

```bash
java -jar $JAR --cms ae-pattern-validator/src/test/resources/cms/test-signed-rsa.p7
```

Output: content-type, signer info, digest algorithm, signature algorithm —
each validated against the registry.

### 3.3 CycloneDX CBOM

```bash
java -jar $JAR --cbom ae-pattern-validator/src/test/resources/cbom/test-cbom.json
```

Output: CBOM components enumerated; each `algorithm` / `primitiveType`

```bash
java -jar $JAR --generate-cbom --cert ae-pattern-validator/src/test/resources/certs/test-rsa-2048-sha256.pem
```

Emits CycloneDX 1.6 CBOM JSON to stdout, derived from the certificate's
cryptographic content.

## 4. Category Taxonomy Queries

The `category:` field on every algorithm entry carries a path-valued
functional taxonomy ([`registry-category-taxonomy.md`](registry-category-taxonomy.md)).
The autogenerated distribution table lives at
`ae-pattern-validator/src/main/resources/registry/README.md` under "Algorithm
Category Distribution".

### 4.1 Show the Distribution Table

```bash
sed -n '/AUTOGEN:BEGIN registry-category-distribution/,/AUTOGEN:END registry-category-distribution/p' \
  ae-pattern-validator/src/main/resources/registry/README.md
```

### 4.2 Count Entries by Top-Level Branch

```bash
python3 -c "
import yaml, glob
from collections import Counter
counts = Counter()
for fn in sorted(glob.glob('ae-pattern-validator/src/main/resources/registry/cr-*.yaml')):
    d = yaml.safe_load(open(fn))
    for e in d['entries']:
        if e.get('type') != 'algorithm': continue
        cat = e.get('category', '?')
        counts[cat.split('/', 1)[0]] += 1
for branch, n in sorted(counts.items(), key=lambda kv: -kv[1]):
    print(f'{n:4d}  {branch}')
"
```

### 4.3 List All Entries in a Specific Category

```bash
# All AEAD constructions
python3 -c "
import yaml, glob
for fn in sorted(glob.glob('ae-pattern-validator/src/main/resources/registry/cr-*.yaml')):
    for e in yaml.safe_load(open(fn))['entries']:
        if e.get('category', '').endswith('/aead'):
            print(f\"{e['id']:30s}  {e.get('category')}\")"
```

```bash
# All KEMs (PQC and classical)
python3 -c "
import yaml, glob
for fn in sorted(glob.glob('ae-pattern-validator/src/main/resources/registry/cr-*.yaml')):
    for e in yaml.safe_load(open(fn))['entries']:
        if e.get('category') == 'asymmetric/kem':
            print(f\"{e['id']:25s}  lifecycle={e.get('lifecycle')}\")"
```

```bash
# All RNG entries grouped by sub-branch
python3 -c "
import yaml, glob
from collections import defaultdict
buckets = defaultdict(list)
for fn in sorted(glob.glob('ae-pattern-validator/src/main/resources/registry/cr-*.yaml')):
    for e in yaml.safe_load(open(fn))['entries']:
        c = e.get('category', '')
        if c.startswith('rng/'):
            buckets[c].append(e['id'])
for c, ids in sorted(buckets.items()):
    print(f'{c} ({len(ids)})')
    for i in sorted(ids):
        print(f'  - {i}')"
```

## 5. Lifecycle Taxonomy Queries

The `lifecycle:` field captures standardisation-process state
([`registry-lifecycle-taxonomy.md`](registry-lifecycle-taxonomy.md)).
Vocabulary: `standardised | draft | selected | candidate | withdrawn | broken
| legacy` + sentinels `unspecific | unknown`.

### 5.1 Show the Distribution Table

```bash
sed -n '/AUTOGEN:BEGIN registry-lifecycle-distribution/,/AUTOGEN:END registry-lifecycle-distribution/p' \
  ae-pattern-validator/src/main/resources/registry/README.md
```

### 5.2 Find Broken Algorithms

```bash
python3 -c "
import yaml, glob
for fn in sorted(glob.glob('ae-pattern-validator/src/main/resources/registry/cr-*.yaml')):
    for e in yaml.safe_load(open(fn))['entries']:
        if e.get('lifecycle') == 'broken':
            print(f\"{e['id']:30s}  category={e.get('category')}\")"
```

### 5.3 Find Algorithms in Draft Standards

```bash
python3 -c "
import yaml, glob
for fn in sorted(glob.glob('ae-pattern-validator/src/main/resources/registry/cr-*.yaml')):
    for e in yaml.safe_load(open(fn))['entries']:

            print(f\"{e['id']:30s}  category={e.get('category')}\")"
```

Expected output: FN-DSA (FIPS 206 IPD), MLDSA44/65/87 (LAMPS Composite
ML-DSA draft), Ascon-AEAD128 / Ascon-Hash256 / Ascon-XOF128 / Ascon-CXOF128
(SP 800-232 draft), XChaCha20 (IETF I-D), BLS, OPAQUE-3DH, cdx:X3DH.

### 5.4 Find Withdrawn Standards


SSL30-PRF, TLS10-PRF, RC4-HMAC, GOSTR3410 (1994 variant), cdx:TLS1-PRF,
cdx:RSA-X931.

## 6. Compound Category × Lifecycle Queries

The motivating use case for both fields together — derive Summary Counts
table rows by combining a functional category with a lifecycle state.

### 6.1 PQC KEMs by Lifecycle

```bash
python3 -c "
import yaml, glob
from collections import Counter
counts = Counter()
for fn in sorted(glob.glob('ae-pattern-validator/src/main/resources/registry/cr-*.yaml')):
    for e in yaml.safe_load(open(fn))['entries']:
        if e.get('category') == 'asymmetric/kem':
            counts[e.get('lifecycle', '?')] += 1
for lc, n in sorted(counts.items(), key=lambda kv: -kv[1]):
    print(f'{n:3d}  KEM {lc}')"
```

### 6.2 PQC Signatures by Lifecycle


### 6.3 Standardised KEMs Only (Production-Ready)

```bash

for e in yaml.safe_load(open('ae-pattern-validator/src/main/resources/registry/cr-pqc.yaml'))['entries']:
```

## 7. Consistency Validation

### 7.1 Run All 14 Checks

```bash
python3 scripts/validate_consistency.py
```

Output: per-check OK/INFO/WARN/FAIL verdict, totals at end. Exit 0 on
success, 1 on any FAIL.

### 7.2 Single Check Snapshot (last three checks — taxonomy work)

```bash
python3 scripts/validate_consistency.py 2>&1 | grep -A1 "12\.\|13\.\|14\."
```

### 7.3 Regenerate All Autogenerated Markdown

```bash
python3 scripts/generate_status_tables_from_yaml.py
```

Touches: `cryptographic-protocol-status.md` (10 sections),
`cryptographic-tls-cipher-suites.md` (14 sections),
`ae-pattern-validator/src/main/resources/registry/README.md` (2 sections:
category + lifecycle distributions). Reports "no changes" if YAML and
markdown are already in sync.

### 7.4 Dry-Run Check (CI-friendly)

```bash
python3 scripts/generate_status_tables_from_yaml.py --check
```

Exit non-zero if any AUTOGEN section is stale. Use as a pre-commit /
pre-merge gate.

Verify everything works in one shot — useful after a fresh checkout or
dependency upgrade.

```bash
cd ae-pattern-validator && mvn -q clean verify
cd ..

# Quick CLI smoke test
JAR=ae-pattern-validator/target/ae-pattern-validator-0.1.0-SNAPSHOT-exec.jar
java -jar $JAR "AES-256-GCM" "ML-KEM-768" "SHA-512" "ChaCha20-Poly1305" "MD5"

# Consistency suite
python3 scripts/validate_consistency.py

# Autogen freshness
python3 scripts/generate_status_tables_from_yaml.py --check
```

Expected: 4 OK + 1 ERROR (MD5 broken); all 14 consistency checks pass;
autogen sections in sync.
